# Phase 5 发布说明

本次发布把系统从固定采购流程工具推进为可配置、可分析、可审计的项目管理平台。AI 能力默认关闭，启用后也只参与解释、建议和受控查询配置，不会绕过现有权限、审批、审计和业务规则。

## 新增能力

- 工作流模板版本化：支持项目类型绑定流程模板，发布后模板不可直接修改，可通过新版本演进；既有采购流程保持兼容。
- 自定义报表：基于白名单 dataset、字段、聚合和筛选条件生成预览、保存报表，并支持定时生成。
- 项目模板库：支持分类、标签、私有/部门/全局模板，并可从模板实例化项目。
- 跨项目对标：按部门、项目类型、分类和标签范围计算周期、预算偏差、环节停留和逾期率。
- 项目风险评分：规则评分为准，AI 仅在启用时生成解释摘要和建议动作。
- 文档类型建议：上传时按模板必传文档、文件名关键词和扩展名给出建议，用户确认后才写入文档类型。
- 自然语言指标问答：把问题映射到自定义报表白名单查询；AI 启用时只能返回受控 query config，不能返回 SQL。

## 兼容性说明

- 默认 AI 配置为 `AI_ENABLED=false`，未配置 provider 时风险评分、文档建议和指标问答均可走规则或内置模板。
- 新增迁移包含项目类型/工作流模板、报表、项目模板和 AI 审计表；升级时必须执行 `alembic upgrade head`。
- 自定义报表和指标问答共享 `ReportQueryCompiler` 权限范围，普通项目成员只能查询自己负责或参与项目的数据。

## 迁移步骤

1. 备份 PostgreSQL 和 `storage/`。
2. 更新代码到发布提交。
3. 更新 `.env`，按需补充 `AI_*` 变量，默认保持关闭。
4. 执行 `docker compose -f docker-compose.prod.yml run --rm backend alembic upgrade head`。
5. 执行 `docker compose -f docker-compose.prod.yml up -d --build`。
6. 完成发布后冒烟测试：工作流模板、报表、模板库、对标分析、风险评分、文档建议和指标问答。

## 已知限制

- 自然语言指标问答只支持白名单 dataset；未映射的问题会拒绝执行。
- AI provider 只支持 OpenAI-compatible `/chat/completions` JSON object 响应。
- 文档类型建议不读取文件正文，当前依据文件名、扩展名、模板必传文档、短摘要和可选 AI 重排。
